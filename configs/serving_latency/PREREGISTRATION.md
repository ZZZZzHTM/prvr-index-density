# End-to-end search latency

Measure original 160-slot fp32, frame Ward-8 40-slot fp32 and frame Ward-8 40-slot int8 sequentially in one process/session on a single L40 using 100,000 physically replicated TVR index entries from GMMFormerV2 seed 9527. Each copy has its own lengths and scales. Use a 1,024-video scoring block and top 100, TF32 disabled, one CPU thread, batches 1 and 128, pre-extracted RoBERTa query features already resident on GPU. The singleton uses the first of the original 128 evenly spaced queries cropped to valid length. Check exclusive GPU use before admission and every 0.5 seconds during measurement. If interrupted by another compute job discard the whole session, wait and rerun all three; never splice sessions. If hardware differs record the actual model.

Keep int8 bytes, FP32 scales and int32 lengths resident. Decode each 1,024-video block during each search without renormalizing or caching full dequantized vectors. Use CUDA synchronization and perf_counter, three warmups and five repeats. Measure encode_query only; separately measure scoring with normalized queries including dequantization and top-k; independently time end-to-end encoding, normalization, scoring and top-k. Report batch-one median total and both stages, batch-128 queries/s (128 divided by total seconds), peak allocated scoring memory after resetting the counter, and resident index bytes. Exclude feature extraction and input transfer. Compare the two fp32 totals to 51.6/31.7 ms with a ±10% tolerance; always finish all three even on a mismatch and report it. Report slower int8 as observed if applicable.
